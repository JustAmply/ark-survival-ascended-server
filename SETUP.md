## Server configuration

Set `ASA_*` variables under your service's `environment` in `docker-compose.yml`.
After editing the service or its referenced `.env` values, run
`docker compose up -d -t 300` to recreate the container with the new settings.
A plain restart reuses the previous environment.

### Choose a map

Each service runs one world. For example, set `ASA_MAP: Ragnarok_WP` to host
Ragnarok. Switching maps loads the selected map's own world save. Before
switching an existing server, [back up the current world](docs/backups.md).

| Official map | What to expect | `ASA_MAP` |
| --- | --- | --- |
| The Island | The original island, from tropical beaches to snowy peaks | `TheIsland_WP` |
| Scorched Earth | Desert survival with extreme heat and sandstorms | `ScorchedEarth_WP` |
| The Center | Ocean exploration, floating islands and underground caverns | `TheCenter_WP` |
| Aberration | Underground survival with climbing, gliding and radiation | `Aberration_WP` |
| Extinction | A ruined city surrounded by wasteland and biome domes | `Extinction_WP` |
| Ragnarok | A large world with Viking ruins, highlands and a desert | `Ragnarok_WP` |
| Valguero | White cliffs, broad valleys and an underground Aberration biome | `Valguero_WP` |
| Genesis Part 1 | Mission-based progression across five simulated biomes | `Genesis_WP` |
| Astraeos (paid DLC) | Greek mythology, islands and coastal exploration | `Astraeos_WP` |
| Lost Colony (paid DLC) | A frozen world centered on the city of Arat Prime | `LostColony_WP` |

For a community world, follow [mods and custom maps](#mods-and-custom-maps).
To keep several worlds online, use the [cluster setup](#multi-server-clusters).

### Launch settings

| Variable | What it controls | Default or supplied example |
| --- | --- | --- |
| `ASA_MAP` | World to load | `TheIsland_WP` |
| `ASA_SESSION_NAME` | Name shown in the server browser | Generated by the game |
| `ASA_PORT` | UDP port players connect to | `7777` |
| `ASA_RCON_PORT` | TCP port for remote administration | `27020` |
| `ASA_RCON_ENABLED` | Enable remote console commands, including the readiness check and shutdown save | `True` |
| `ASA_SERVER_ADMIN_PASSWORD` | Authenticate RCON and in-game admin access | Required by the supplied Compose file. Legacy runtime fallback is `changeme`. |
| `ASA_SERVER_PASSWORD` | Password players enter to join | Unset |
| `ASA_SPECTATOR_PASSWORD` | Password for spectator access | Unset |
| `ASA_MAX_PLAYERS` | Maximum players at once | Compose sets `50` |
| `ASA_CLUSTER_ID` | Identify servers that allow transfers between their worlds | Compose sets `default` |
| `ASA_CLUSTER_DIR` | Shared directory holding cluster transfer data | Compose sets `/home/gameserver/cluster-shared` |
| `ASA_MODS` | Comma-separated CurseForge mod IDs to load | Unset |
| `ASA_BATTLEYE` | Set to `false` to disable BattlEye anti-cheat | Unset |
| `ASA_EXTRA_QUERY_PARAMS` | Additional ARK query options separated by `?` | Unset |
| `ASA_EXTRA_FLAGS` | Additional space-separated launch flags | Unset |

To supply credentials as Docker secrets or require an explicitly configured
admin password, see [password files](docs/secrets.md).

Use the extra parameters for options without a dedicated variable:

```yaml
environment:
  ASA_EXTRA_QUERY_PARAMS: "AllowFlyerCarry=True?ForceRespawnDinos=True"
  ASA_EXTRA_FLAGS: "-servergamelog -NoTransferFromFiltering"
```

### Legacy launch strings and precedence

`ASA_START_PARAMS` remains supported:

```yaml
environment:
  ASA_START_PARAMS: TheIsland_WP?listen?Port=7777?RCONPort=27020?RCONEnabled=True -WinLiveMaxPlayers=50
```

It supplies the base launch line. Individual variables replace the matching
entries while preserving unknown options. Precedence, highest first:

1. `ASA_EXTRA_QUERY_PARAMS` / `ASA_EXTRA_FLAGS`
2. Named `ASA_*` launch variables
3. `ASA_START_PARAMS`
4. Built-in defaults

The runtime always adds `-nosteam`.
Use [configuration diagnostics](docs/diagnostics.md) to inspect effective launch
settings with passwords redacted.

## Storage and backups

The supplied Compose file uses named volumes:

| Volume | Container path | Contents |
| --- | --- | --- |
| `server-files-1` | `/home/gameserver/server-files` | Game files, saves, configuration, `mods.json` and Proton compatibility data |
| `steam-1` | `/home/gameserver/Steam` | Installed Proton builds |
| `steamcmd-1` | `/home/gameserver/steamcmd` | SteamCMD installation |
| `cluster-shared` | `/home/gameserver/cluster-shared` | Shared character and creature transfer data |

Game configuration is under `ShooterGame/Saved/Config/WindowsServer` within
the server-files volume. Actual volume names include the Compose project prefix;
host paths also depend on Docker's installation. Inspect the mounts rather than
assuming a fixed `/var/lib/docker` path:

```bash
docker inspect asa-server-1 --format '{{json .Mounts}}'
```

Container recreation preserves named volumes. Removing those volumes, including
with `docker compose down -v`, deletes the data. For offline backups, scheduled
retention and verified restores, follow [backup and recovery](docs/backups.md).

## Networking

| Default port | Protocol | Purpose |
| --- | --- | --- |
| `7777` | UDP | Player connections |
| `27020` | TCP | RCON administration |

Compose publishes only the UDP game port. Allow it through the host and cloud
firewalls and, behind a home router, forward it to the Docker host. If you
change `ASA_PORT`, adjust the UDP mapping and those rules accordingly.

RCON stays enabled inside the container network. Health checks, shutdown saves
and commands such as the following work without a published TCP port:

```sh
docker compose exec asa-server-1 asa-ctrl rcon --exec 'listplayers'
```

RCON sends the admin password and commands without encryption. To use a
desktop RCON client remotely, add the following entry under the service's
existing `ports` list, alongside the UDP entry:

```yaml
- "127.0.0.1:27020:27020/tcp"
```

If you changed `ASA_RCON_PORT`, use that value as the container port (the
rightmost number). Apply the change with `docker compose up -d` during a
maintenance window because Compose recreates the service. On your workstation,
open a tunnel to the Docker host using your SSH login:

```sh
ssh -N -L 127.0.0.1:27020:127.0.0.1:27020 user@docker-host
```

Keep the SSH session open and connect the client to `127.0.0.1:27020` with
the server admin password. Only SSH needs to be reachable for this connection.

## Server management

For start, stop and image update commands, see [after your first session](README.md#after-your-first-session).
To check configuration, permissions or live readiness, see [diagnostics](docs/diagnostics.md).

### Mods and custom maps

Use CurseForge mod IDs. If you maintain a fixed list in Compose, set
`ASA_MODS: "12345,67891"` and recreate the service. To manage mods from the host
without editing Compose, use the built-in database. Replace `12345` with your
mod's ID:

```bash
docker compose exec asa-server-1 asa-ctrl mods enable 12345
docker compose exec asa-server-1 asa-ctrl mods list --enabled-only
docker compose restart -t 300 asa-server-1
```

Restarting activates the enabled list. Use `mods disable 12345` to keep a mod's
entry for later, or `mods remove 12345` to delete it. Run `mods list` to include
disabled entries. The server combines enabled database entries with `ASA_MODS`
and removes duplicates. To stop loading a mod, remove it from each source that
enables it. For an unreadable database, see [mod database recovery](docs/mod-safety.md).

For a custom map, enable its mod ID, set `ASA_MAP` to the level name supplied by
the author, then recreate the service to apply both changes.

### ServerAPI plugins

To use the optional ASA ServerAPI loader, place its `AsaApi_*.zip` archive in
`ShooterGame/Binaries/Win64/` inside the server-files volume. On the next
launch the runtime extracts the archive there, removes the processed ZIP and
starts `AsaApiLoader.exe` when present. Install individual plugins according to
their authors' instructions.

### RCON

```bash
docker compose exec asa-server-1 asa-ctrl rcon --exec 'saveworld'
docker compose exec asa-server-1 asa-ctrl rcon --exec 'serverchat Hello players!'
```

The tool reads the port and admin password from the launch configuration, then
checks `GameUserSettings.ini` for missing values.
See [RCON troubleshooting](FAQ.md#rcon-commands-fail) for connection failures.

## Multi-server clusters

Uncomment the second service **and its volume declarations** in the supplied
Compose file. Give each server distinct game/RCON ports and separate server,
Steam and SteamCMD volumes. All members of a cluster must share the same
`ASA_CLUSTER_ID`, mount the same `cluster-shared` volume and set
`ASA_CLUSTER_DIR` to its container path. Choose a cluster ID for the whole
cluster rather than a different ID for each member.

Apply the configuration with `docker compose up -d -t 300` and open each server's game
port in the firewall/router.

## Restarts and shutdown

The supervisor attempts `saveworld` through RCON, waits, then stops the server.

| Variable | Default | Purpose |
| --- | --- | --- |
| `ASA_SHUTDOWN_SAVEWORLD_DELAY` | `15` | Seconds after saving before shutdown |
| `ASA_SHUTDOWN_TIMEOUT` | `180` | Graceful shutdown seconds before forced cleanup |
| `SERVER_RESTART_DELAY` | `15` | Seconds before relaunch |

The supplied Compose services set `stop_grace_period: 300s` so ordinary stops
and recreation allow saving and shutdown to finish. The examples also use
`-t 300` for existing deployments. Increase both if you increase runtime delays;
custom Compose files should include the same grace period on every server.

The supplied Compose file schedules a restart at 04:00. Configure the schedule
with a five-field cron expression in the container's `TZ` timezone:

```yaml
environment:
  SERVER_RESTART_CRON: "0 4 * * *"
  SERVER_RESTART_WARNINGS: "30,5,1"
```

Warnings are comma-separated minutes before the restart (default `30,5,1`). The scheduler uses the
same save and shutdown sequence; the container stays running. Remove or empty
`SERVER_RESTART_CRON` to disable scheduled restarts.

### Crash recovery

Preparation errors and runs shorter than 120 seconds count as consecutive
failures. `ASA_RESTART_MAX_FAILURES=5` stops the supervisor after five failures;
`0` allows unlimited retries. Retry delays grow from `SERVER_RESTART_DELAY` up
to `ASA_RESTART_MAX_DELAY=300` seconds (never below the base delay). Scheduled
restarts and runs of at least 120 seconds reset the counter. ARM64's existing
safe-profile policy can stop earlier. Avoid an unconditional external restart
policy if you want this limit to require operator intervention.

## Startup and Proton

### Game updates and validation

SteamCMD installs missing game files automatically. Use `ASA_UPDATE` to choose
when to check an existing installation for updates:

| `ASA_UPDATE` | When the game updates |
| --- | --- |
| `always` (default) | Every server launch, including supervised restarts |
| `startup` | Once per container process |
| `manual` | Install only when the server executable is missing |

For a planned update in manual mode, switch to `startup`, recreate the service
during maintenance, then restore `manual` and reapply. `ASA_VALIDATE` selects
when SteamCMD checks file contents **during an install or update**:

| `ASA_VALIDATE` | Behavior |
| --- | --- |
| `first` (default) | Validate the initial install, then update without full checksums on later starts |
| `always` | Validate every install or update to check for damaged game files |
| `never` | Skip validation, including on the first install |

Full validation reads every installed file. For slow starts, compare the
`Initial ownership setup`, `Server file update completed` and
`Proton preparation completed` durations in the logs before changing settings.
Compare initial setup with a restart using the same volumes.

### Proton version and verification

GE-Proton is downloaded automatically. When no version is pinned, the runtime
selects a compatible latest release and falls back to its known baseline if
selection or preflight fails. A failed explicitly pinned build causes startup
to fail instead of silently replacing the pin.

| Variable | Purpose |
| --- | --- |
| `PROTON_VERSION` | Pin a build, for example `10-34`; omit for automatic selection |
| `PROTON_SKIP_CHECKSUM` | `1` bypasses archive verification; use only as a temporary last resort |
| `PROTON_SKIP_PREFLIGHT` | `1` skips the host-library launch check |

The preflight result is cached for each Proton build and image version, so it
is not repeated on every restart. If logs report missing libraries, update the
image; see [startup troubleshooting](FAQ.md#proton-reports-a-missing-library).

## ARM64 experimental

Set the service image to
`ghcr.io/justamply/asa-linux-server:arm64-experimental` or
`ghcr.io/justamply/asa-linux-server:<version>-arm64-experimental`.
Use a published image digest when you need an unchanged deployed image.
Translation works without privileged mode or a `/dev/fuse` mount.

| Variable | Default | Purpose |
| --- | --- | --- |
| `ASA_TRANSLATOR_MODE` | `auto` | Select FEX on ARM64; `fex` requires it explicitly, `none` disables translation |
| `ASA_TRANSLATOR_PROBE_TIMEOUT` | `120` | Seconds allowed for the startup translation probe |
| `ASA_PROTON_PROFILE` | `balanced` | `safe` disables esync/fsync |

The runtime checks translation before downloading the game. Two consecutive
translated server runs that each exit within 120 seconds switch the retry
profile to `safe`. An early exit while using `safe` stops the supervisor,
including when you selected that profile yourself. Preparation errors do not
trigger the retry policy. Keep persistent volumes for downloaded tools and game data.

ARM64 remains experimental until full ARK startup, saving and sustained operation
have been verified on the target host. For errors, see [ARM64 troubleshooting](FAQ.md#arm64-translation-fails).
Build and translation design details belong to [ADR 0002](docs/adr/0002-isolated-arm64-translation.md).

## Resource tuning and debug mode

Use `ASA_LOG_LEVEL` to change log verbosity (default `INFO`).
The runtime raises the soft file-descriptor limit to the hard limit and logs
the Wine synchronization backend. The supplied Compose file sets both `nofile`
limits to `524288`. If logs warn about the slow server path, check those limits.
Size memory limits and swap to the host, map and mods; monitor actual usage with
`docker stats asa-server-1` before choosing limits.

For an interactive container that holds startup:

1. Set `ENABLE_DEBUG: "1"` in Compose.
2. Apply with `docker compose up -d -t 300`.
3. Open a shell with `docker compose exec asa-server-1 bash`.

Set `ENABLE_DEBUG` back to `"0"` and reapply to resume normal startup.
